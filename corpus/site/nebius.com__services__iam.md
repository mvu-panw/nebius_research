## Google or GitHub accounts

Users don’t need to create additional accounts: to access your Nebius resources, they can use any of their Google or GitHub accounts.

## Single Sign-On

Users can log in to Nebius services using Single Sign-On (SSO) with their corporate accounts by configuring user federation with their identity provider.

## Inviting users

Users with administrative permissions can invite others to join their tenant. Invitations can be accepted by users logged in via Google, GitHub or corporate SSO.

## Service accounts

Users can create service accounts to grant access to cloud resources via service APIs for automation scenarios.

## User groups

Users can be organized into groups, each with specific access rights to cloud resources.

## Questions and answers about IAM

What is Identity and Access Management used for?

IAM service is designed to help you manage user accounts, control access to resources and configure access rights. You can:

- invite new cloud users,

- manage access rights to resources by adding users to the groups,

- create service accounts — special accounts to manage Nebius resources via API,

- get an IAM token required for authorization via API.

How much does it cost to use the service?

Identity and Access Management is provided free of charge.

How are access rights verified?

Before performing an operation with a resource, the service checks whether the user has the necessary permissions. If the user (or service account) doesn’t have any of the permissions, the operation isn’t performed and Nebius service returns an error.
